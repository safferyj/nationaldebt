Executive summary

nationaldebt.au is a polished, fast and fully offline single-file data story. It covers Australian Government (Commonwealth) general-government debt, budget balances and interest from 1970-71 to 2025-26. Its data engineering is mostly exemplary. I re-derived every embedded input from primary sources, and all of the following match exactly:

  • 362 of 366 fiscal amounts;
  • all 56 GDP values;
  • all 112 CPI index values;
  • all 56 population denominators.

The provisional 2025-26 population is exactly reproducible from the documented method.

One material data error is published. The 2002-03 values for gross debt, net debt, net interest and interest paid are copies of the 2000-01 values.

  • Where the error came from. It first appears in the PBO’s 2026-27 Budget workbook. All nine earlier PBO vintages still linked from the PBO website, and the site’s own cited source (FBO 2025-26 Appendix B), give the correct values.
  • How the repository made it worse. It treated the problem as affecting ratios only and recalculated the two ratios from the wrong amounts. It then published a note on the page vouching for those amounts. Its agent instructions also tell future contributors to preserve the “correction”.
  • Effect. The page shows 2003-04 as the largest single-year fall in gross debt in 56 years (−17.5%). The correct figure is −4.7%.

The second major problem is keyboard accessibility:

  • Tab and Space are captured for the whole document, so Tab changes the chart view instead of moving focus.
  • All focus indicators are removed.
  • The skip link can never become visible.

Together these mean a keyboard-only user cannot move through the page.

The tests cover a very wide range of devices, but they don't check the thing that matters most for this site. No test validates data or calculations, there is no CI, and a full run is 620 test executions, so repository policy discourages running it.

How it happened
  • The first upload (deeb934, 5 September 2026) imported the defective row.
  • Commit d507755 (“Audit embedded fiscal and political data”, 7 September) diagnosed the problem as ratios only. It replaced them with 66,403 / 804,444 and 46,802 / 804,444, which made the wrong amounts look internally consistent.
  • The Definitions section publishes a “Source-audit exception” saying the ratios “do not reconcile with that workbook's own dollar and GDP cells”. That wrongly implies the dollar amounts are right.
  • AGENTS.md says: “The documented 2002-03 PBO ratio correction … Preserve them”.

  • Update AGENTS.md.
  • Add a regression test (Appendix C).
  • Consider notifying the PBO.

High D2 — In real terms, “change in debt” can contradict the plotted real debt level

In Real mode, getDebtChangeDollars() converts the nominal change using the current year's CPI factor: (Dt − Dt−1) × B/Pt. The debt level plotted on the same chart is Dt × B/Pt. The difference between the two is the inflation erosion of the opening stock of debt.

As a result, in 17 of 110 year-and-series pairs the “change” has the opposite sign to the movement of the real line beside it:

  • 2023-24, gross debt: the page shows +$18.2b, but the plotted real gross debt falls by $17.8b.
  • 1979-80, gross debt: +$6.8b shown, against a fall of $10.4b.
  • 2022-23, gross debt: −$6.0b shown, against a fall of $65.5b.

The Definitions describe the method, but the label “Change in gross debt” under a “Real” toggle will be read as the change in real debt.

In per-capita mode the series is the change in debt per person, Δ(D/P), which is not the same as the change in debt divided by population. For 2022-23 these are −A$1,032 and −A$205 respectively. The label “Gross debt change per capita” doesn't make clear which one is shown.

Recommendation: make the chart self-consistent. In Real and per-capita modes, plot the change in the plotted series and label it “Change in real gross debt” or “Change in gross debt per person”. If the current measure is still wanted, keep it only in the CSV under an explicit name such as gross_debt_change_nominal_in_2025_26_dollars.

Medium D3 — Annual flows are attributed to the government in office on 30 June

The 30 June convention is correct for debt, which is measured on that date. Budget balances and interest, however, cover the whole year. In 7 financial years the governing party changed: 1972-73, 1975-76, 1982-83, 1995-96, 2007-08, 2013-14 and 2021-22. In each of these the tooltip and measure buttons pair the full year's result with the incoming government.

For example, the 2021-22 tooltip reads “Labor: Albanese, Chalmers … Cash balance −1.4% Deficit” (Figure 4). Yet Albanese took office on 23 May 2022, five weeks before the year ended, and the 2021-22 Budget was framed and delivered by the previous government.

Recommendation: flag transition years explicitly, for example “Transition year: Coalition → Labor (23 May 2022)”, in the government measure button, the tooltip and the government band. A brief neutrality note would also help. This matters for a politically salient site.

Medium D4 — Notes on comparability over time are missing

FBO Appendix B, which the site cites, lists several structural breaks, and the page presents the 56-year series without mentioning any of them:

  • classification differences before 1976-77;
  • cash accounting up to 1997-98, with accrual-derived cash data afterwards;
  • debt instruments valued at historic cost before 1999-2000 and at market value afterwards, which affects net debt and net interest;
  • net debt before 1999-2000 taken from ABS publications, and before 1987-88 from Treasury estimates;
  • AAS/IFRS reporting from 2005-06;
  • AASB 16 leases from 2019-20, which affects net debt.

Separately, “Change in net debt” includes valuation effects. For example, rising bond yields lower the market value of Australian Government Securities (AGS), so this measure is not purely borrowing.

Recommendation: add a “Comparability” note to the Definitions section, quoting the FBO wording. Consider adding small markers on the chart at 1998-99, 1999-2000 and 2019-20.

Medium D5 — Licensing: the primary source is licensed “NonCommercial-NoDerivatives”

The PBO website states that its material is licensed CC BY-NC-ND 4.0. The site transcribes the PBO workbook and redistributes derived series in its CSV. It is also unclear whether the site is non-commercial. Whether copyright subsists in the numbers themselves is a legal question, so seek advice or PBO permission.

The same series for every year from 1970-71 to 2025-26 are published in FBO 2025-26 Appendix B, which is the official Treasury and Finance source. It is licensed CC BY 4.0 (“© Commonwealth of Australia 2026”; see the FBO preliminary pages). The ABS is also CC BY 4.0.

Recommendation:

  • Make FBO Appendix B the primary source and keep the PBO workbook as a cross-check. This would also have prevented D1.
  • Add explicit CC BY attribution statements.
  • State a licence for the site's own CSV and code. The repository has no LICENSE file.

Low D6 — Provenance could be more precise

The source list is already better than most: it gives exact workbook and data-cube URLs, and the CPI table and series ID. To make the page fully auditable:

  • Add a retrieval date and SHA-256 checksum for each source file.
  • Name the GDP series (Table 34, A2304617J), the population series (A2133251W) and the FBO tables (B.1–B.6).
  • Note that the ratio and gross-debt-growth columns are derived. The code comment says the rows were “transcribed” from the PBO workbook, but the workbook has no growth column.
  • Give the CSV a companion metadata file or flag columns: the source for each value, whether it is provisional (2025-26 population), and whether an FBO value was substituted (2025-26).

Low D7 — Dead link to the Parliament of Australia

The “Governments and oppositions” link to aph.gov.au/…/Practice7/HTML/Chapter3/… redirects to the APH content system's “Page not found” (HTTP 404). Replace it with the current edition of House of Representatives Practice, or with the Parliamentary Handbook's ministry lists.

Low D8 — Minor labelling and method choices

  • The government measure button says “Liberal” for Coalition governments. “Coalition” is more accurate.
  • For 1975–82, the Coalition partner was the National Country Party.
  • “2025-26 dollars” means June-quarter-2026 prices for debt stocks but average 2025-26 prices for annual flows. The two bases differ by about 1.3% (102.31 / 101.015). Say so near the Real toggle or axis label.
  • Per-capita flows are divided by the 30 June population rather than the average for the year. This is acceptable, but should be documented.
  • Office start dates are shown as dd.mm.yyyy. Australian readers expect a format like “23 May 2022”.

What is done well

  • The values were transcribed accurately and consistently, apart from D1. There is no mixing of GDP vintages, and the 2024-25 GDP revision is documented.
  • The stock/flow distinction for inflation adjustment (June-quarter against financial-year-average CPI) is correct and explained.
  • The provisional 2025-26 population is labelled clearly and can be reproduced exactly.
  • Careful definitions: interest paid under PBO note (g), the Future Fund treatment in the underlying cash balance, and the warnings that a change in debt is not the Budget result.
  • The 2013 Treasurer-date conflict was resolved properly using an archived official source.
  • Sources are grouped by role (direct inputs, political timeline, background), with exact file URLs.

2. Code quality and agent maintainability

Strengths

  • The page has no runtime dependencies and makes no network requests, and the page works offline.
  • The code has clearly marked DATA UPDATE POINT blocks with provenance comments.
  • Startup fails loudly if CPI or population data is missing.
  • The code has named helpers for derived values and consistent escaping via esc().
  • scripts/build.js generates the pop-up text from Markdown, with section validation and link-safety checks. It is currently in sync: I regenerated it in memory and it matched index.html.
  • Development dependencies are pinned exactly, and the commit messages are descriptive.

High C1 — AGENTS.md is stale and tells agents to preserve defects

Coding agents follow AGENTS.md closely, so errors in it tend to be repeated in future changes. Current problems:

  • It says to preserve “the documented 2002-03 PBO ratio correction” (D1).
  • It describes “Tab/Shift+Tab cycle lenses … Space moves the legend” as part of the UI contract (U1).
  • It describes the table, table-row selection, insights, the selected-year details panel, sourceLink() and inline citations. None of these exist in index.html; only dead .insight-card CSS remains, and the sources[].id values are never referenced.
  • It gives the scope as “1970-71 to 2024-25”, and so does government-debt-by-tier-notes.md.
  • It documents the legacy trailing false placeholder instead of removing it.

Recommendation: rewrite AGENTS.md from the current code. Add a rule: “data corrections must cite a second official source; never preserve an audit exception without re-verification”. Add a contract that keyboard navigation (Tab order and focus visibility) must never be overridden.

Medium C2 — Derived values are stored and maintained by hand, and the vintage is hard-coded

  • fiscalRows stores five %-of-GDP ratios and gross-debt growth alongside the amounts they are calculated from. Fixing D1 therefore means editing six cells across two rows by hand, and the 2024-25 and 2025-26 ratios were recalculated by hand. Either compute them at runtime, or validate the stored values against computed ones at startup.
  • cpiBase repeats the last CPI row. Derive it from the chosen base year instead.
  • “2025-26” appears 40 times in index.html, only 3 of them in the data arrays, and 21 times in the tests; “1970-71” appears 10 times. The others are in comments, button titles, usage text, axis labels, reset-button titles and definitions. Derive range and base-year labels from rows so that updating to a new vintage is a data-only change.

Medium C3 — A single large file with complex interaction state

index.html is 4,953 lines and 197 KB: about 1,770 lines of CSS and about 2,970 lines of script and data. File views cut off at about 20 KB, so an agent needs at least 10 paged reads to see the whole file, and targeted edits risk side-effects elsewhere.

The interaction layer has 73 addEventListener call sites, several capture-phase listeners on the whole document, and at least 8 module-level flags that suppress or restore clicks (for example suppressNextChartTooltipClick, dismissedChartTooltipPointerId and suppressNativeControlClickButton). The git history shows a long run of touch-handling fixes, which suggests this area is fragile.

Recommendation: keep the single-file deliverable, but write it from modules such as src/data.js, calc.js, render.js, interactions.js and styles.css, and assemble them with scripts/build.js. Export pure calculation functions so they can be unit-tested in Node. Model pointer and touch gestures as an explicit state machine.

Low C4 — Dead code, naming collisions and duplicated text

  • chartModes has only one mode (debt), yet the code still has 6 state.mode === "debt" checks and 4 chartModes[state.mode] lookups.
  • 8 selector lines of unused .insight-card and .insight-number CSS remain.
  • row.grossChange holds growth %, but the series key grossChange means a change amount. This is an easy source of mistakes.
  • The same instruction text of about 800 characters appears three times (static aria-label, runtime aria-label and <desc>), and the copies have already drifted apart.

Low C5 — Deployment and configuration

  • GitHub Pages publishes the repository root. removed.html is therefore public and indexable: it has no noindex and still refers to 2024-25 purchasing power. AGENTS.md, tests/ and package.json are public too.
  • There is no custom 404 page, no LICENSE and no Content-Security-Policy <meta>. GitHub Pages cannot set response headers.
  • .github/mcp.json runs @playwright/mcp@latest, which is unpinned and requires Google Chrome. The server failed in this environment for that reason.

Publishing a built dist/ folder via GitHub Actions would fix most of these.

Low C6 — Robustness

  • document.querySelector(location.hash) throws on fragments that are not valid selectors. For example, https://nationaldebt.au/#2025 raises an uncaught error: “'#2025' is not a valid selector”. Use getElementById(decodeURIComponent(hash.slice(1))).
  • The dashed cursor line for the selected year is drawn on top of the selected point and intercepts pointer events at its centre. Add pointer-events: none.
  • renderSources() inserts source.url into href without esc(). The data is static, so the risk is low, but this breaks the repository's own convention.
  • CSV values are unrounded floats, for example 833.1506248629687.

High T1 — No tests of data integrity, sources or calculations

Nothing checks that ratios match their amounts, that growth matches consecutive values, that no year repeats another year's block (which would have caught D1 immediately), that the fields match a snapshot of the official source, or that the derived helpers are correct. The helpers are defined inline, so Node cannot import and test them.

Only the most recently updated row has golden values. Nothing protects the other 55 years from regressions.

High T2 — No CI, and a matrix too expensive to run

There is no .github/workflows folder. GitHub Pages deploys whatever is pushed. The repository's own instructions tell agents not to run the suites unless explicitly asked, because they take so long. In practice, deployments are not gated on tests.

Many of the 200 profiles are near-duplicates (for example the landscape variants of the same device). A representative set of 6–8 profiles on each pull request, with the full matrix nightly, would give most of the value for well under a tenth of the cost. For example, 6 mobile profiles × 3 tests plus the 4 desktop profiles × 5 tests is 38 executions instead of 620.

Low T3 — Fragile or missing checks

  • There are 28 waitForTimeout calls; the history includes a commit to make tests “resilient to host load”.
  • Some assertions use fixed pixel constants, for example firstPointX toBe(75).
  • Some assertions check page copy, for example "28,019,400-person proxy".
  • One mobile test runs the entire checklist.
  • No test loads a shared URL and checks that the view is restored; only selected is exercised.
  • There is no link checker, which is why the dead APH link went unnoticed.
  • There is no check that index.html is in sync with popup-text.md.
  • There are no accessibility tests. An axe scan and a Tab-walk test would have caught U1 and U4.

Recommended test architecture

  1. npm run test:data (Node, under 1 second): schema and length checks; ratios and growth recomputed from amounts; duplicate-block detection; complete CPI and population coverage; comparison with a committed JSON extract of FBO Appendix B, including its checksum; timeline contiguity.
  2. npm run test:unit: calculation module fixtures, including the D2 cases.
  3. npm run test:a11y: axe on the key states, plus a keyboard walk (skip link, navigation, controls, source links, CSV button).
  4. Playwright on the representative profile set; the full matrix nightly.
  5. A weekly link check and a build-sync check (build.js --check).

4. User experience and accessibility

Strengths

  • A distinctive, high-contrast visual design.
  • Fast: one 197 KB HTML file (45 KB with gzip), interactive in about 1.2 s through a TLS-inspection proxy, and no third-party requests.
  • The measure buttons give the selected year's values at a glance, with a clear Surplus/Deficit badge.
  • Rich zoom and pan, share links with a manual-copy fallback, and a one-click CSV of the full dataset.
  • Definitions written in plain English.
  • Careful touch handling on mobile.

Critical U1 — Keyboard users cannot navigate the page

I checked this in headless Chromium against the live site.

  • After the page loads, pressing Tab four times leaves focus on <body>. Instead of moving focus, it cycles the chart view: Dollars/Absolute/Nominal → Real → Per capita/Nominal → Per capita/Real. The handler calls preventDefault() on Tab across the whole document.
  • Space on a focused “Usage” <summary> does not open it, although Enter does. Space never scrolls the page.
  • :focus, :focus-visible { outline: none !important } removes every focus indicator, and nothing replaces it.
  • The skip link stays at left: -9999px even when focused.
  • 17 unmodified character keys (0–5; Q, W, E, R, T; A, S, D, F, G; and L) act as global shortcuts, and there is no way to turn them off.

WCAG criteria failed: 2.1.1 Keyboard (A), 2.4.3 Focus Order (A), 2.4.1 Bypass Blocks (A), 2.1.4 Character Key Shortcuts (A) and 2.4.7 Focus Visible (AA).

Recommendation:

  • Never intercept Tab.
  • Make the chart card a focusable group, and handle Space, arrows and letter shortcuts only while focus is inside it.
  • Add a visible :focus-visible ring.
  • Reveal the skip link on :focus.
  • Add an option to disable single-key shortcuts.

High U2 — Phones in landscape are blocked

On touch screens in landscape up to 900 px wide, every element except a notice is hidden (body > *:not(.landscape-warning) { display: none !important }). This fails WCAG 1.3.4 Orientation (AA). It is also counter-intuitive, because a wide time-series chart suits landscape. Provide a compact landscape layout, for example the chart with the controls collapsed.

Medium U3 — No headline, scope or “data current to” statement

The page has no <h1>, no subtitle and no visible statement of what is covered. Nothing says it is the Commonwealth general-government sector only, excluding the states, or which sources and date the data is current to. The <title> is just “nationaldebt.au”.

Definitions, sources and caveats sit in collapsed sections below the fold. On phones the page opens in full-screen mode, with the navigation and all of that context hidden.

Recommendation: add a single line above the chart that also appears in full-screen mode. For example: “Australian Government general-government debt and budget balances, 1970-71 to 2025-26 · Source: Final Budget Outcome 2025-26, ABS · Updated 29 Sep 2026”.

Medium U4 — Automated accessibility findings (axe-core 4.13, WCAG 2.2 AA plus best practice)

  • aria-prohibited-attr (serious, 56 nodes): the chart points are <circle aria-label> elements without a role that allows a label.
  • color-contrast (serious): the Surplus/Deficit badge text.
  • page-has-heading-one (moderate).

Beyond axe:

  • The chart's aria-label is an instruction paragraph of about 800 characters, which screen readers announce every time the chart receives focus. Use a short name and aria-describedby pointing to the usage section.
  • There is no prefers-reduced-motion handling for the legend animation or smooth scrolling.

Medium U5 — Values clipped inside the measure buttons

I rendered the page at six desktop sizes from 1024 to 1920 px wide using the Linux fallback font (DejaVu Sans). Nothing is clipped at 1024 or 1280 px. At 1366 px “Gross debt change” wraps onto two lines, and at 1440, 1536 and 1920 px “Gross debt growth” wraps as well. In each case the value overflows the fixed-height button by about 7 px.

This depends on the font; I did not check it with Segoe UI or SF Pro. It shows that the buttons don't reflow when text gets longer, which is also a risk under WCAG 1.4.4 and 1.4.12 (text resize and text spacing). Use min-height instead of a fixed height, or switch to short labels based on measured width.

Low U6 — Other UX issues

  • Share links lose their state. The shared-view parameters are removed from the address bar after load (history.replaceState), so reloading or bookmarking a shared link loses the view.
  • The x-axis sits below the fold at 1024×768, 1280×800, 1366×768, 1440×900 and 1536×864.
  • Mixed units on one axis. When Gross debt growth is shown, it shares the axis with %-of-GDP measures. The 82.4% spike in 2008-09 compresses every other series. Use a second axis or a small separate panel.
  • Government band. It has one-year gaps between segments that can read as periods with no government. Rudd's 2013 segment is 2 px wide, and there is no on-chart colour key.
  • Hard-to-discover interactions. The zoom-box keyboard sequence and the two-finger gestures are explained in a single bullet of about 190 words.
  • Disabled controls. Absolute/Per capita and Nominal/Real are shown but disabled in % of GDP view.
  • CSV gaps. The CSV has no real-dollar values, CPI factors, provisional or substitution flags, or source metadata; units are implied only by column-name suffixes.

5. Other aspects

Medium O1 — Governance and trust

The About section says only that the site was “Made with care in September 2026 using GPT-5.6 Luna (max)” and links to the repository. It names no accountable owner, gives no contact or corrections process, and has no changelog of data revisions and no “last updated” line.

For a dataset about politics and the public finances, add:

  • a named maintainer;
  • a “Report an error” link (for example, to GitHub issues);
  • a corrections log, starting with D1.

Low O2 — Discoverability and sharing

The page title is generic, and there are no Open Graph, Twitter card or canonical tags, so shared links show bare previews. There is also no robots.txt, no sitemap and no custom 404 page, while removed.html is public (see C5).

Privacy, security and performance are strong.

  • No cookies, analytics or third-party requests.
  • URL parameters are checked against a fixed list of allowed values.
  • Dynamic text is escaped, and the pop-up text is built with link validation.
  • The page is a single 197 KB HTML file (45 KB with gzip) plus a favicon.
  • The only additions I'd suggest are a CSP <meta> and an explicit referrerpolicy.

Appendix C — Suggested data-validation test (Node, no browser)

This sketch runs in well under a second and would have flagged D1. It assumes the data arrays are moved to a module that can be imported, or are read from index.html as in this review.

// tests/data.test.mjs — run with: node --test tests/
import test from "node:test";
import assert from "node:assert/strict";
import { fiscalRows, cpiDeflators, populationByFinancialYear } from "../src/data.js";
import fbo from "./fixtures/fbo-2025-26-appendix-b.json" with { type: "json" }; // committed extract + source SHA-256

const F = ["fy","gdp","gross","grossPct","grossGrowth","net","netPct","ucb","ucbPct","hcb","hcbPct","fb","fbPct","netInt","agsInt"];
const rows = fiscalRows.map((r) => Object.fromEntries(F.map((k, i) => [k, r[i]])));

test("ratios reconcile with amounts and GDP", () => {
  for (const r of rows) for (const [v, p] of [["gross","grossPct"],["net","netPct"],["ucb","ucbPct"],["hcb","hcbPct"],["fb","fbPct"]]) {
    if (r[v] == null) continue;
    assert.ok(Math.abs(r[v] / r.gdp * 100 - r[p]) < 0.0006, `${r.fy} ${p}`);
  }
});

test("no year repeats another year's debt/interest block", () => {
  const seen = new Map();
  for (const r of rows) {
    const key = [r.gross, r.net, r.netInt, r.agsInt].join("|");
    assert.ok(!seen.has(key), `${r.fy} duplicates ${seen.get(key)}`);
    seen.set(key, r.fy);
  }
});

test("amounts match the official FBO Appendix B extract", () => {
  for (const r of rows) for (const k of ["gross","net","ucb","hcb","fb","netInt","agsInt"]) {
    if (fbo[k][r.fy] === undefined) continue;
    assert.equal(r[k], fbo[k][r.fy], `${r.fy} ${k}`);
  }
});

test("every year has CPI and population", () => {
  const cpi = new Set(cpiDeflators.map(([fy]) => fy));
  for (const r of rows) { assert.ok(cpi.has(r.fy)); assert.ok(populationByFinancialYear.get(r.fy) > 0); }
});
